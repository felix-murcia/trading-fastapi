# P0.2c Backfill Audit Report Summary

## 🔍 Key Findings

**1. Why 89 of 96 filled orders lack mt5_order_id:**
- 96 filled orders exist in `orders` table (status='filled')
- Only 7 have `mt5_order_id` populated (7.3%)
- The remaining 89 lack `mt5_order_id` because the webhook `/v1/ai/trade/filled` only sends `order_db_id`, not `mt5_order_id`
- The `_mark_trade_order_filled` function only updates `mt5_order_id` if `order_db_id` is provided
- 89 of 96 filled orders don't have `order_db_id` linked (they're the 90 outcomes with position_id but no order_db_id)

**2. Can outcome.position_id be used to populate orders.mt5_position_id?**
- **No.** The auditor confirmed "NO overlaps" between outcome.position_id and orders.mt5_position_id
- 90 outcomes have position_id but no order_db_id
- Only 7 position_id values exist in both tables, but none match on symbol+direction+status
- Backfill script requires exact match on position_id+symbol+direction

### 3. Can the 121 outcomes without position_id be linked?
- **No.** These outcomes have no position_id field at all
- They only contain symbol, direction, and other fields like entry_price
- No exact matching criteria exists to link them to orders
- The backfill script only supports matching on position_id+symbol+direction

### 4. Viability of temporary cross-matching orders with deals MT5
- **Not viable** - introduces high risk of incorrect matches
- Time-based matching could match different market conditions
- Price/volume matching could match different orders
- Would corrupt backfill data and affect trading decisions

### 5. What code change prevents recurrence?
- **Fix the webhook**: Add `mt5_order_id` to `/v1/ai/trade/filled` payload
- Currently webhook only sends `order_db_id` (which is NULL for unlinked outcomes)
- The `_mark_trade_order_filled` function already expects `mt5_order_id` as parameter
- **Required change**: Make `mt5_order_id` mandatory in webhook payload

## 🚨 Critical Issues
| Issue | Impact | Severity |
|-------|--------|----------|
| 89 filled orders lack mt5_order_id | Cannot link to orders | Critical |
| 90 outcomes with position_id but no order_db_id | No exact match possible | Critical |
| 121 outcomes without position_id | No possible exact match | Critical |
| Webhook design flaw | Prevents proper linking | Critical |

**Phase 2 (Optimization):**

## 💡 Key Insight
The system is **not broken** - it's **misconfigured**. The webhook design requires `mt5_order_id` to properly link trade outcomes to orders, but this field is missing from the payload. Adding this field will enable full recovery of all linked data.
